# 已认领设备信息面板设计

## 意图与目标

重新组织已认领设备时的右侧信息面板，优先展示会话操作提示和解绑入口，并利用垂直空间展示更多设备信息。用户反馈当前设备信息集中在顶部、提示与解绑按钮固定在底部，造成信息和操作分散、留白明显；窄栏中底部操作也不易及时看到。

## 非目标

不调整手机投屏主体、设备操作方式、未认领态的批量下发流程或租约行为；不新增需设备权限或耗时采集的运行指标。

## 设计决定

用户已确认采用“顶部控制区 + 连接状态 + 完整设备详情”的方案，并同意 Android 增加品牌、SDK 版本和屏幕密度信息；窄栏优先保留提示、解绑和连接状态，再隐藏次要信息。

- 已认领态右栏改为自上而下的控制面板：会话提示与解绑操作在顶部，连接/投屏状态及刷新操作紧随其后，设备详情在下方。
- 设备详情扩充到适配器现有能力可稳定提供的范围。Android 展示品牌、系统版本、SDK 版本、分辨率、屏幕密度、连接方式和设备 ID；HarmonyOS/iOS 显示各自实际返回的字段，不以空字段占位。
- 使用容器宽度响应式样式，在窄栏下保留顶部会话控制、连接状态和核心设备识别信息，逐级隐藏低优先级详情；宽栏显示完整详情。
- 采用紧凑的分组/键值布局填充可用空间，不新增图表或对用户无帮助的虚构状态。

## 方案比较

1. 保持底部固定控制区，只增加设备字段：能填充留白，但窄栏时提示和解绑仍处于视觉末端。
2. 顶部固定控制区，下面排列连接状态和完整设备详情，并按栏宽隐藏低优先级字段：兼顾控制优先级、信息密度与窄栏可用性。选用此方案。
3. 将提示挪到投屏画面下方：减少右栏内容密度，也会挤占有限的投屏空间，不采用。

## 约束与实现范围

现有布局、容器查询和设备信息呈现均位于 `plugin/client.js`。设备属性由平台 adapter 提供并由 `plugin/host/registry.js` 聚合：Android 已提供 brand、sdk、density、osVersion、width、height、connection；HarmonyOS/iOS 提供较少字段。实现需沿用现有 token、React createElement 和无依赖 CSS 模式，并确保未认领态样式不变。

## 验收标准

- 已认领态的提示和解绑操作出现在右栏顶部，不再被 `margin-top:auto` 推到底部。
- 连接状态/刷新排在设备详情之前。
- Android 展示 brand、SDK、density 等已有信息；其它平台只呈现实际存在的值。
- 窄栏宽度下顶部控制与连接状态可见，低优先级字段按设计隐藏；宽栏显示完整详情。
- 未认领态及投屏主体布局无变化；现有 client 与 routes 测试通过。
